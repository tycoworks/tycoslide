# Plugin Distribution Architecture

Status: **Design** (not yet implemented)

## Problem

A tycoslide theme IS a Claude Code plugin. The plugin zip needs to contain everything an agent needs to build slides — but the theme is private (company branding), so we can't rely on public npm.

## Current State

The zip contains only skill files:
```
.claude-plugin/plugin.json
skills/build/SKILL.md
skills/build/manifest.json
skills/build/references/*.md
```

This gives the agent instructions and template metadata, but no runtime code.

## Target Architecture

```
tycoslide-theme-default.zip
├── .claude-plugin/plugin.json      # Plugin manifest
├── skills/build/                   # Skill files (SKILL.md, manifest.json, references/)
├── hooks/hooks.json                # SessionStart hook for automatic npm install
├── bin/tycoslide                   # Wrapper script (added to agent's PATH)
├── runtime-package.json            # Lists @tycoslide/cli + core + sdk as deps
└── theme.tgz                      # npm pack output (private theme code + assets)
```

## Key Claude Code Plugin Infrastructure

- `${CLAUDE_PLUGIN_ROOT}` — substituted variable pointing to the extracted plugin directory (read-only)
- `${CLAUDE_PLUGIN_DATA}` — persistent writable directory (`~/.claude/plugins/data/{id}/`) for node_modules, survives plugin updates
- **SessionStart hook** — runs automatically when plugin loads
- **`bin/` directory** — executables added to agent's PATH while plugin is enabled

## How It Works

### 1. SessionStart hook installs dependencies automatically

`hooks/hooks.json`:
```json
{
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "diff -q \"${CLAUDE_PLUGIN_ROOT}/runtime-package.json\" \"${CLAUDE_PLUGIN_DATA}/package.json\" >/dev/null 2>&1 || (cp \"${CLAUDE_PLUGIN_ROOT}/runtime-package.json\" \"${CLAUDE_PLUGIN_DATA}/package.json\" && cd \"${CLAUDE_PLUGIN_DATA}\" && npm install && npm install \"${CLAUDE_PLUGIN_ROOT}/theme.tgz\" && npx playwright-core install chromium) || rm -f \"${CLAUDE_PLUGIN_DATA}/package.json\""
          }
        ]
      }
    ]
  }
}
```

Pattern from official docs. It:
- Compares bundled `runtime-package.json` against cached copy in `${CLAUDE_PLUGIN_DATA}`
- On first run or change: copies it, runs `npm install` (pulls public deps from npm), installs theme from bundled tarball, installs Playwright Chromium
- On failure: removes cached package.json so next session retries

### 2. `runtime-package.json` lists public dependencies

Generated by the compiler from the theme's package.json:
```json
{
  "name": "tycoslide-theme-default-runtime",
  "version": "0.3.0",
  "private": true,
  "dependencies": {
    "@tycoslide/cli": "^0.3.0",
    "@tycoslide/core": "^0.3.0",
    "@tycoslide/sdk": "^0.3.0"
  }
}
```

### 3. `theme.tgz` bundles private theme code

Output of `npm pack` — includes `dist/`, `assets/`, `package.json`. The private theme never touches a public registry.

### 4. `bin/tycoslide` wrapper resolves from plugin data dir

```bash
#!/usr/bin/env bash
export NODE_PATH="${CLAUDE_PLUGIN_DATA}/node_modules"
exec node "${CLAUDE_PLUGIN_DATA}/node_modules/@tycoslide/cli/dist/index.js" "$@"
```

Agent just runs `tycoslide build deck.md` — no path knowledge needed.

### 5. SKILL.md Dependencies section becomes declarative

No manual install instructions. Just:
> Dependencies are installed automatically when this plugin loads (via SessionStart hook).

## Implementation Changes Needed

1. **`packages/sdk/src/plugin/compiler.ts`** — generate `hooks/hooks.json`, `bin/tycoslide`, `runtime-package.json`
2. **`packages/cli/src/compileTheme.ts`** — run `npm pack`, include new files in zip
3. **`docs/SKILL.md`** — replace Dependencies section with declarative note

## Size

Theme tarball dominated by `assets/tycoslide/background.png` (~2.5MB). Full zip ~3.2MB. Acceptable.
